# Projektstudie mobile Unternehmensanwendungen - Device Inventory

## Abstract

Im Rahmen der Veranstaltung "Projektstudie Entwicklung von mobilen Unternehmensanwendungen (**282160**)" wird eine webbasierte Anwendung zur zentralen Verwaltung von IT-Endgeräten in Unternehmen entwickelt. Das System soll den gesamten Lebenszyklus von Geräten – von der Erfassung über die Zuweisung an Mitarbeiter bis zur Wartung und Ausmusterung – nachvollziehbar abbilden. Neben der Geräteverwaltung sollen insbesondere Benutzer- und Rollenverwaltung, Statusverwaltung, Gerätezuweisungen sowie eine Historisierung relevanter Änderungen umgesetzt werden.

## Ausgangssituation

Unternehmen verwalten eine Vielzahl unterschiedlicher IT-Geräte wie Notebooks, Smartphones, Tablets oder Monitore. Dabei müssen Informationen über Gerätebestand, aktuellen Zustand und die Zuordnung zu Mitarbeitern nachvollziehbar verwaltet werden.

## Fragestellung

Wie kann eine webbasierte Device-Management-Anwendung gestaltet und umgesetzt werden, mit der Unternehmensgeräte und deren Lebenszyklus zentral, rollenbasiert und nachvollziehbar verwaltet werden können?

## Zielsetzung

Ziel des Projekts ist die Entwicklung einer funktionsfähigen webbasierten Device-Management-Anwendung.

## Erwartete Ergebnisse

Als Projektergebnis wird eine lauffähige Webanwendung erwartet, die mindestens folgende Funktionen bereitstellt:

- Benutzeranmeldung und Rollenverwaltung
- Geräteverwaltung
- Gerätezuweisung und -rückgabe
- Verwaltung des Gerätestatus
- Geräte- und Zuweisungshistorie
- Suche und Filterung
- Audit-Logging relevanter Aktionen
- übersichtliche Weboberfläche

Optional können Funktionen wie QR-Codes, Wartungsverwaltung, **CSV**-Import/-Export, Dashboard oder Benachrichtigungen ergänzt werden.

## Vorgehensweise der Aktivitäten

Die Entwicklung erfolgt iterativ auf Basis von Scrum. Eine Iteration dauert gemäß Veranstaltung zwei Wochen; über das Semester sind 6–7 Iterationen vorgesehen. Jede Iteration umfasst Planung, Entwicklungsarbeiten, Präsentation der lauffähigen Software und Retrospektive.

Innerhalb der Sprints werden Anforderungen verfeinert und anschließend Design, Implementierung, Tests und Dokumentation durchgeführt. Diese Aktivitäten entsprechen ebenfalls dem vorgesehenen Entwicklungsablauf der Veranstaltung.
